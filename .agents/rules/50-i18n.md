# 50-i18n: Locale, Direction & Translation Standards

Detailed architectural rationale: @docs/standards/RTL_AND_I18N.md

## 1. Locale & Direction Source of Truth
- **Locale drives direction**: `locale` (`'en' | 'fr' | 'ar'`) is the sole persisted source of truth. Direction (`'ltr' | 'rtl'`) is strictly derived via `getDirectionForLocale(locale)` (`ar` → `'rtl'`; `en`, `fr` → `'ltr'`). Never persist a separate `dir` cookie that could drift from `locale`.
- **First-paint zero-flash SSR**: Never rely solely on a client `useEffect` to set `dir`/`lang` on `<html>`. In Next.js Server Components, read the `locale` cookie via `getServerI18nState()` and stream `<html lang={locale} dir={direction}>` on first paint.
- **Single-source client persistence & host-level refresh**: When `setLocale(newLocale)` runs on the client, persist to the `locale` cookie (`SameSite=Lax`) and invoke an optional host `onLocaleChange` callback (wired in `src/app/` to `router.refresh()`, keeping `next/navigation` strictly out of shared `providers/`). Do not write write-only storage keys that nothing reads.

## 2. Strictly Typed `t(key, params)` & Starter Namespace Isolation
- **Strict compile-time keys (no silent fallbacks)**: `t(key: TranslationKey, params?: Record<string, string | number>)` accepts ONLY valid `TranslationKey` paths and optional interpolation parameters—NEVER widen `TranslationKey` with `| (string & {})` and NEVER pass inline English fallback strings (`t(key, 'Fallback')` is forbidden). Every locale dictionary must satisfy `MessageShape<typeof en>` without `any`.
- **Zero hardcoded copy or inline ternaries**: Every user-facing string, button label, placeholder, empty/error message, `aria-label`, and `title` tooltip outside pure `components/ui/` (which receives localized strings via props) must pass through `t(key, params)`. Never write `isRtl ? '...' : '...'` or hardcoded demo copy in `fixtures/`, `patterns/`, `layouts/`, `wireframes/`, or `app/`.
- **Starter namespace isolation**: Shared namespaces (`common`, `errors`) mirror across starters; product-specific namespaces and message registration stay isolated (`dashboard`, `settings` in Dashboard only; `website` in Website only), protected explicitly in `scripts/sync-shared.mjs`.

## 3. Bi-directional (Bidi) Text & Data-Driven Formatting
- **Isolate embedded LTR tokens**: Whenever numbers, percentages (`+12.5%`), currencies, phone numbers, tracking IDs, emails, URLs, channels (`#general`), or code tokens appear inside localized text, wrap them in `<BidiText dir="ltr">` (`<bdi>` with `unicode-bidi: isolate`). Add `lang="..."` only when the token is actual foreign human-language prose, not on language-neutral IDs, phones, or numbers.
- **Data owns currency; locale owns display**: Format numbers, currencies, percentages, dates, and relative times via `useI18n()` formatters (`formatNumber`, `formatCurrency`, `formatPercent`, `formatDate`, `formatRelativeTime`). Always pass the record's explicit currency (`formatCurrency(amount, record.currency, options)`)—switching UI language must NEVER silently convert `USD` into `EUR` or another currency. `formatPercent(value)` expects fractional input (`0.125` → `12.5%`).
