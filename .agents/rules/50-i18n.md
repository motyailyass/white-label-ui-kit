# 50-i18n: Locale, Direction & Translation Standards

Detailed architectural rationale: @docs/standards/RTL_AND_I18N.md

## 1. Locale & Direction Source of Truth
- **Locale drives direction**: `locale` is the primary source of truth. Direction (`'ltr' | 'rtl'`) is strictly derived from locale (`ar`, `fa`, `ur`, `he` → `rtl`; `en`, `fr` → `ltr`). Standalone direction toggles are dev-only tools.
- **First-paint zero-flash SSR**: Never rely on a client `useEffect` to set `dir` on `<html>`. In Next.js Server Components, read `dir` and `locale` cookies via `getServerI18nState()` and stream `<html lang={locale} dir={direction}>` on the first paint.
- **Client persistence**: When switching direction or locale, write to `document.cookie` (`SameSite=Lax`) and `localStorage` to preserve the user's choice across reloads.

## 2. Translation via Namespaces & `t()`
- **No silent fallbacks**: Translations are typed against English (`satisfies MessageShape<typeof en>`). A missing key is a compile-time TypeScript error, not a broken screen in production.
- **No inline ternaries**: Do not hardcode `isRtl ? 'عربي' : 'English'`. All user-facing strings must pass through `t(key, fallback, params)`.
- **Per-namespace separation**: Messages are organized into modular namespace files (`common`, `dashboard`, `settings`, `errors`) per locale (`en`, `fr`, `ar`).

## 3. Bi-directional (Bidi) Text Isolation
- **Prevent punctuation bleed**: Whenever numbers, phone numbers, tracking IDs, usernames, or code fragments appear inside Arabic text, isolate them with `<BidiText>` / `<bdi>` and `unicode-bidi: isolate;`.
- **Native formatting**: Format all numbers, currencies, dates, and relative times using native zero-dependency `Intl` APIs (`formatNumber`, `formatCurrency`, `formatDate`).
