Quick start

Requirements: Node.js 22 or newer and pnpm 12. Enable pnpm through Corepack if it is not installed yet.

corepack enable
git clone https://github.com/motyailyass/white-label-ui-kit.git
cd white-label-ui-kit
pnpm install

Then run the starter you want:

# Dashboard — canonical shared source
cd typescript/nextjs/starterkit/dashboard
pnpm dev

# Website
cd typescript/nextjs/starterkit/website
pnpm dev

# Vite dashboard (mirrored core, single overview screen)
cd typescript/vite/starterkit/dashboard
pnpm dev

There is no published npm package yet. Add a primitive to an existing project with npx github:motyailyass/white-label-ui-kit add button (CLI guide), or copy the starter you need and keep the files you want — the kit is designed to be edited, not imported as a locked dependency.

Architecture

Dependencies flow one way. A lower tier never imports an upper tier.

  1. Host routes — src/app/. Next.js metadata, routing, Link, and Image wiring.
  2. Product composition — layouts, shell, website sections, and templates.
  3. Connected patterns — bind useI18n() and useTheme() to pure primitives.
  4. Core primitives — components/ui/. Props in, events out; no i18n, router, query, or form libraries.
  5. Foundation — tokens, presets, providers, and the i18n engine.

The shared rule: edit shared files in dashboard/src, then run pnpm run sync:shared from the repository root. Editing a mirrored file only in website/src or the Vite app is overwritten by the next sync.

pnpm run sync:shared         # mirror dashboard/src into website + Vite
pnpm run sync:shared:check   # fail on drift (CI gate)

Design tokens

Components consume semantic roles, never raw values. Tokens live in src/styles/tokens/; each starter owns its local preset in src/styles/dashboard/ or src/styles/website/.

Layers and motion

Document-level layers use a fixed ten-step scale: --z-sticky 100, --z-dropdown 200, --z-drawer 310, --z-modal 410, --z-toast 500, --z-tooltip 600. Arbitrary numbers such as 9999 are rejected by review.

Transitions use four durations — instant 0ms, fast 120ms, normal 180ms, slow 240ms — and three easings. Under prefers-reduced-motion: reduce every duration collapses to 0ms and continuous animations stop. Focus outlines never transition.

Depth is product-owned: the dashboard is 100% shadow-free and separates surfaces with borders and surface steps. Website shadows are opt-in semantic roles.

RTL & i18n

Locale is the single source of truth. Direction is derived: ar renders RTL; en and fr render LTR. The locale cookie is read on the server so the first paint already has the right lang and dir.

  • Keys are typed: t('dashboard.layouts.classicTitle'). Missing keys fail compilation; there are no English fallbacks in code.
  • Every user-facing string, placeholder, and aria-label goes through t().
  • Numbers, currencies, percentages, dates, and relative times use the locale formatters. A record's own currency always wins over the display locale.
  • Embedded LTR tokens — IDs, numbers, phone numbers, URLs — are wrapped in <BidiText dir="ltr">. Only actual foreign prose gets a lang attribute.
  • CSS uses logical properties only: padding-inline, margin-block, inset-inline-start. Directional icons mirror automatically.

Try it on real components: open the gallery, switch the language, then flip the preview direction.

Testing

Every primitive ships with a Vitest and React Testing Library test. Overlays and layout behavior are covered with Playwright. Bug fixes include a regression test.

CommandRun from
pnpm lintEach app directory
pnpm type-checkEach app directory
pnpm testEach app directory
pnpm test:e2eDashboard or website
pnpm run sync:shared:checkRepository root
pnpm run check:shadowsRepository root
pnpm run check:clientRepository root
pnpm run format:checkRepository root
node --test cli/index.test.mjsRepository root (CLI)

Run the smallest check first. The full gate above runs before handoff and in CI.

Publishing the gallery

This site is assembled from two sources: the hand-written pages in site/ and a static export of the dashboard app, which contains the real mounted gallery.

node scripts/build-gallery-site.mjs   # writes _pages/
npx serve _pages                      # preview locally

The script builds the app with output: 'export' and basePath: '/white-label-ui-kit', drops the app root so the landing page keeps /, excludes test-only fixtures, and adds .nojekyll so Pages serves the _next asset directory. The Pages workflow runs it on every push to main.

Gallery is not a screenshot.

Every page under /gallery/ is the exported app: real primitives, real keyboard behavior, real language switching. The same pages run in development with pnpm dev.
